# Markion

Markion は Rust と GPUI で構築されたネイティブデスクトップ Markdown エディタです。応答性の高いソース編集、ソースに裏付けられたビジュアル編集モード、ライブプレビュー、ワークスペースツール、多形式エクスポートを、軽量な単一アプリケーションにまとめています。Markdown が常にドキュメントの正規形式です——Electron、Tauri、WebView は使用していません。

## インストール

最新ビルドは [GitHub Releases](https://github.com/willmove/markion/releases) からダウンロードしてください。

| プラットフォーム | リリースパッケージ | ターゲット |
|---|---|---|
| Windows | NSIS `.exe` インストーラー | x86_64 |
| Linux | `.deb` と AppImage | x86_64 |
| macOS | `.app` と `.dmg` | Apple Silicon（arm64）、macOS 11+ |

リリースはプラットフォームのコード署名を行っていません。Windows SmartScreen では「詳細情報 → 実行」が必要な場合があり、macOS Gatekeeper ではアプリを右クリックして「開く」を選ぶ必要がある場合があります。**ヘルプ → 更新を確認…** はすべてのプラットフォームで実行可能な更新プロンプトを提供します。タグ付きの Windows x86_64 NSIS インストールでは、cargo-packager Minisign による暗号学的に検証されたワンクリックのダウンロード＆インストールが利用でき、未保存の変更があるドキュメントが存在する間は起動を拒否します。macOS と Linux では、対応するリリースファイルをシステムブラウザーで開きます。Intel Mac では Rosetta 経由で arm64 ビルドを実行できます。ユニバーサルバイナリと Apple 公証は現在提供していません。

## 編集モード

Markion には 4 つのビューモードがあります。デフォルトは分割プレビューです。

- **編集** — 生の Markdown ソースに集中するエディタです。
- **ビジュアル編集** — WYSIWYG 優先、ソースに裏付けられた編集画面です。本文はレンダリングされた状態を保ち、必要な構文だけを段階的に表示します。通常のフェンスコードの内容、ブロック数式、登録済みダイアグラム（Mermaid）、インライン画像フィールド、GFM テーブルセルには、正確な直接エディタが用意されています。WYSIWYG レンダリングがまだ実装されていない構造——YAML フロントマター、インデントコード、不正形式またはバイト対応が曖昧な構文——は、移行措置として正確なソースベースの編集経路を維持しており、[ビジュアル編集 WYSIWYG カバレッジマトリックスとロードマップ](docs/visual-editing-quality.md)で追跡されています。スラッシュコマンドパレットとコンパクトな右クリックブロックコンテキストメニューは、正確なブロック変換（段落、見出し、リスト、引用、フェンスコード、区切り線、テーブル）、複製、上下移動、ソース安全なドラッグ並べ替え、削除を提供します。選択コンテキストの書式ツールバーとビジュアルリンクエディタは、操作ごとに正確なソース変更を 1 回だけ実行します。Markdown の区切り文字はデフォルトで自動ペアリングされ、`:shortcode` で絵文字補完が開き、タスクリストのチェックボックスは直接切り替えられます。見出し・リスト・タスク・引用行からカーソルが離れると、その行はすぐにレンダリングされた表示に戻ります。これは独立したリッチテキストのドキュメントモデルではありません——基盤となる Markdown が常に唯一の正規データです。
- **分割プレビュー** — ソースとレンダリングプレビューを左右に並べて表示します。オプションの同期スクロール設定を有効にすると、ドキュメント全体のスクロール率ではなく、ソースマッピングに基づいて両ペインを同じドキュメント位置に保ちます。
- **閲覧** — 編集不可のレンダリングビューです。デフォルトでは読みやすい最大幅 860 px で中央配置されます。「プレビュー幅自動調整」を有効にするとペイン全体を使用できます。

モードを切り替えても、アクティブなドキュメント、カーソルと選択範囲、元に戻す履歴、タブごとのスクロール状態は保持されます。

**表示 → ソース/分割プレビュー** コマンド（Windows/Linux は `Ctrl+/`、macOS は `Cmd+/`）は、2 つのソース指向レイアウトを切り替えます。ビジュアル編集または閲覧モードから初めて実行すると、編集モードに入ります。

## ドキュメントとワークスペース

- マルチタブ編集。タブごとにカーソル、選択範囲、スクロール、元に戻す/やり直し、プレビュー、アウトライン、キャッシュされた派生 Markdown 状態を保持します。
- すでに開いている Markdown またはプレーンテキストファイルを再度開くと、重複タブを作成せずに既存のタブにフォーカスします。
- **フォルダーを開く** はワークスペースのルートを切り替え、「ファイル」サイドバーに Markdown ファイル、厳選されたプレーンテキストファイル（`.txt`、`.text`、`.log`、`.csv`、`.tsv`、`.org`、`.rst`、`.adoc`/`.asciidoc`）、サポートされている画像ファイル（`.png`、`.jpg`/`.jpeg`、`.gif`、`.webp`、`.bmp`、`.tif`/`.tiff`、`.svg`）をフォルダー階層の下に入れ子で表示します。空のフォルダーも一覧表示されます。Markdown は視覚的に区別され、プレーンテキストファイルは UTF-8 テキストとして開き、画像ファイルは読み取り専用の画像タブとして開き、特大画像はコンテンツ領域に収まるように調整されます。
- フォルダーを展開するとちょうど 1 レベル下の子だけが表示されるため、深く入れ子になったワークスペースも 1 レベルずつ掘り下げられます。
- **非表示ファイルを表示** 設定（デフォルトはオフ）を有効にすると、ドットファイル項目と Windows の隠しファイル属性の両方が表示されます。常に除外されるビルド・依存関係・VCS のノイズ（`target`、`node_modules`、`.git` など）は、いかなる場合も非表示のままです。
- ファイルツリーの右クリックメニューは、対象に応じて、開く、新しいタブで開く、ファイル/フォルダーの作成、名前の変更、削除、システムのファイルマネージャーで表示、フィルター、再読み込みの各操作を提供します。
- ファイルとフォルダーはその場で命名できます。空でないフォルダーの削除には追加の確認が必要です。
- OS のファイルマネージャーから Markion に Markdown ファイルをドラッグできます。
- 「ファイル」と「アウトライン」パネルは表示を切り替えられ、サイドバーと分割ペインの区切り線はドラッグで調整できます。
- 「アウトライン」パネルはドキュメントの見出し階層を折りたたみ可能なツリーとして一覧表示します。子孫を持つ各見出しには展開/折りたたみコントロールが表示され、アウトラインは最初は完全に展開され、折りたたみ状態はドキュメントごとかつセッション内のみで、カーソルのあるセクションがハイライトされます。見出しをクリックするとそのソース位置にジャンプします——閲覧モードではレンダリングされた見出しにジャンプします。
- ネイティブウィンドウのタイトルは、Markion のブランド名の後にアクティブなファイル名を表示し、未保存の変更がある場合は `*` を付けます。ステータスバーには保存状態と一時的な操作フィードバックに加えて、コンパクトな永続コンテキスト（アクティブなドキュメントの文字数と単語数、編集画面がある場合のカーソルの 1 始まりの行・列、ドキュメントまたはワークスペースがリポジトリに属する場合の現在の Git ブランチ）が表示されます。
- **バックアップと同期** は、ワンクリックの「今すぐ同期」フローと平易なステータス表示で、ノートフォルダーを同期先で保護します。安全なバージョン履歴は Git が支え、技術的な操作は「Git の詳細」に収められています。セットアップ、認証、競合、復旧については[バックアップと同期ガイド](docs/git-sync.md)を参照してください。

## Markdown の編集とプレビュー

- パースには `pulldown-cmark` を使用し、CommonMark と GFM をサポートしています。
- 書式コマンドは、段落（Windows/Linux は `Ctrl+0`、macOS は `Cmd+0`）、見出し、太字、斜体、インラインコード、リンク、画像、リスト、タスクリスト、引用、フェンスコードブロック、ソース Markdown テーブルをカバーします。「段落」は交差する ATX 見出しを通常のテキストに戻し、見出し以外の行は変更しません。
- Markdown 自動ペアは、ソースおよびサポートされているビジュアル編集フィールドでデフォルトで有効です。区切り文字のペアリング、選択範囲の囲み込み、既存の閉じ側のスキップ、Backspace による空ペアの削除が可能です。IME 変換中、およびコード・ブロック数式・ダイアグラムのペイロードエディタ内では無効のままです。
- 単語の境界で未閉鎖の `:shortcode` を入力すると、ソースとビジュアル編集で絵文字補完が開きます。確定すると正規の Markdown が挿入され、1 回の元に戻せるソース編集として保持されます。
- Word、Google ドキュメント、Web ページからコピーしたリッチテキストを貼り付けると、クリップボードの HTML フレーバーが書式付き Markdown（見出し、強調、リンク、入れ子リスト、テーブル、コード）に変換され、1 回で元に戻せる操作になります。プレーンテキストのクリップボードはそのまま逐字貼り付けられます。
- 見出しコマンドはデフォルトで H1–H5 を表示し、設定で H1–H6 に拡張できます。
- 検索と置換は、大文字小文字の区別、正規表現、次/前への移動、現在の項目の置換、すべて置換をサポートします。
- ソーステーブルコマンドは、テーブルの書式整備と、行・列の追加、削除、移動が可能です。ビジュアル編集のテーブルではさらに、ソースに裏付けられたセルの直接編集、Tab による移動、決定的な幅の再配置、同じ行/列操作を提供します。通常のプレビューテーブルは読み取り専用のままです。
- 画像リソースワークフローは、クリップボード画像、ドラッグされたファイル、明示的なファイル/URL 挿入、既存のドキュメント画像を取り込みます。ポリシーにより、保持、コピー/ダウンロード、PicGo HTTP・PicGo Core・リテラルなカスタムコマンドによるアップロードを選択できます。詳しくは[画像の取り扱いとアップロードガイド](docs/image-handling.md)を参照してください。Markion は衝突に強いドキュメント相対リソースを使用し、画像メタデータを正確に保持し、転送復旧データを Markdown の外に保持します。
- YAML フロントマターは解析され、プレビューでは非表示になります。`title`、`author`、`date` はエクスポートメタデータに反映されます。
- ドキュメントの書き込みは同一ディレクトリでの原子的な置き換えで、書き込みに失敗しても既存のパスとダーティ状態を保持します。Markion は最後に確認したディスク上のファイル同一性を追跡し、保存前とドキュメントを開いている間に外部変更を検出し、クリーンなドキュメントのみを自動的に再読み込みし、ダーティなドキュメントには再読み込み・上書き・コピー保存の競合選択肢を提示します。復旧マネージャーは、すべての復旧スナップショットを元のパスとディスクとの関係とともに一覧化し、読み取り不能または未選択のデータを削除せずに、復元、破棄、すべて復元、すべて破棄をサポートします。
- 自動保存はデフォルトで 5 秒間入力がないと実行され、未保存ドキュメントの復旧コピーを書き込みます。復元された復旧スナップショットは、正常な保存、明示的な破棄、または原子的に書き込まれた後継に置き換えられるまで永続します。

レンダリングプレビューがサポートするもの：

- 太字、斜体、取り消し線、インラインコード、リンク、ハイライト、上付き、下付き、脚注（参照にホバーすると定義を読めます）、タスクリスト、一般的な絵文字ショートコード、自動リンク。
- ドキュメント内の `[TOC]` / `[toc]` トークンはライブでクリック可能な目次としてレンダリングされ、`[text](#heading)` / `{#id}` の見出しジャンプはドキュメント内にとどまります。
- 正しい順序付きリストの開始番号、入れ子リスト、深さごとの箇条書き記号、ぶら下げインデント、画像、埋め込み HTML。
- サポートされているインライン HTML は、混合 Markdown、スタンドアロン HTML ブロック、テーブルセル、ビジュアル編集のすべてで一貫したセマンティクスを持ち、安全なカラー span、リンクとリンク画像、`kbd`/`samp`、記述どおりの改行、正しく配置された上付き/下付きを含みます。不正形式または未サポートのマークアップは、スクリプトを実行せずに安全にフォールバックします。
- プレビューテキストは選択可能で、コンテキストメニューからプレーンテキスト、Markdown、HTML としてコピーでき、該当する場合はリンクアドレスのコピーもできます。
- `$...$` インライン数式と `$$...$$` ブロック数式は、組み込みの RaTeX（KaTeX 互換）エンジンにより、バンドルされたフォント付きでオフラインに SVG へ組版されキャッシュされます——ネットワークアクセスも外部 LaTeX のインストールも不要です。
- ` ```mermaid ` フェンスダイアグラム（フローチャート、シーケンス図など）は、サニタイズされキャッシュされた SVG にレンダリングされます。
- フェンスコードの構文ハイライトには syntect と two-face の拡張文法セットを使用し、未対応言語にはフォールバックレキサーと任意の行番号表示があります。

## テーマ、言語、設定

- 14 の組み込みテーマ：Paper、Ink、Solar、Forest、Rose、Graphite、GitHub Light/Dark、Solarized Light/Dark、One Light/Dark、Tokyo Night/Light。
- カスタムテーマは Markion のローカルテーマディレクトリにある `.toml` ファイルを使用します。初回使用時に `typewriter.toml` サンプル（オプションの `[fonts]` テーブル——`editor`、`rendered`、`code`——を含み、ユーザーに明示的な指定がない場合に Markdown ソースエディタ、レンダリング本文、コード画面のフォントファミリーを提供します）が開始点としてインストールされます。レガシーな `.theme` ファイルは初回読み込み時に自動移行されます。
- 7 つのインターフェース言語：英語、簡体字中国語、繁体字中国語、日本語、フランス語、ドイツ語、スペイン語。
- アプリ内の設定パネルでは、**一般** タブに言語、サイドバー表示、プレビュー幅自動調整、集中/タイプライターモード、Markdown 自動ペア、コード行番号、同期スクロール、非表示ファイルを表示、見出しメニューの深さを、**外観** タブにテーマ、プレーンごとのフォントファミリー（ソース、読書、コード）、フォントサイズ、段落間隔を用意しています。
- 設定は `config.toml` に永続化されます。レガシーな `preferences.conf` は自動移行されます。

すべての設定フィールドは省略可能です。主なデフォルト値とファイル限定の設定は次のとおりです。

```toml
theme = "Paper"
language = "en"
focus_mode = false
typewriter_mode = false
code_line_numbers = true
preview_adaptive_width = false
heading_menu_max_level = 5        # 5 または 6
sync_scroll = false
sidebar_visible = true
sidebar_tab = "files"             # "files" または "outline"
show_hidden_files = false
markdown_auto_pair = true

# プレーンごとのオプションのフォントファミリー。省略時はテーマに従い、
# 次に組み込みデフォルト（ソース/読書はシステム UI フォント、コードは JetBrains Mono）。
# editor_font_family = "Cascadia Code"
# rendered_font_family = "Georgia"
# code_font_family = "JetBrains Mono"

[auto_save]
enabled = true
delay_secs = 5

[git]
background_check = false

[export]
pdf_engine = "xelatex"
```

設定、復旧ファイル、テーマ、日次ローテーションの診断ログは、プラットフォームに適した Markion データディレクトリを使用します。起動前に `RUST_LOG=debug` を設定すると、より詳細なログが得られます。

## エクスポート

Markion のエクスポート先：

- WeChat 向けリッチコンテンツを準備するためのローカル MarkNice ワークスペース
- Markdown
- スタイル付き HTML とプレーン HTML
- LaTeX
- DOCX
- PDF
- PNG と JPEG のテキストスナップショット

PDF と DOCX は、まず取り込まれた Typune/pandoc エクスポートエンジンを試みます。pandoc または選択した PDF エンジンが利用できない場合、Markion はより単純な組み込みライターにフォールバックし、使用したバックエンドをステータスバーに表示します。pandoc と適切な PDF エンジンをインストールすると、よりリッチな出力が得られます。PNG/JPEG と組み込み PDF 出力は、意図的に基本的なテキストスナップショットに留めています。

## Word のインポート

**ファイル → Word（.docx）をインポート** を選ぶと、1 つの DOCX を完全にローカルで新しい保存済み Markdown ドキュメントに変換します。Markion は保存ピッカーの前に変換レポートを表示し、内容が失われる可能性がある場合は明示的な選択を求めます。サポートされている埋め込み画像は Markdown の隣の `<ファイル名>.assets/` に保存されます。このディレクトリは `.md` ファイルと一緒に保持してください。インポーターはリソースに上限があり、キャンセル可能で、オフラインで動作し、既存の Markdown やアセットパスを決して上書きしません。変更履歴は「承諾後のビュー」で取り込まれ、Word の見出しレベルをより忠実に保持し、太字と語の境界を相互運用性の高い Markdown に正規化します。レガシーな `.doc`、`.docm`、暗号化ファイル、PDF/OCR、ページレイアウトの再現はこのワークフローの対象外です。サポートされる意味サブセット、制限、診断、クリーンアップの動作については [`docs/word-import.md`](docs/word-import.md) を参照してください。

**エクスポート → WeChat向けに公開（MarkNice）** を選ぶと、アクティブなインメモリドキュメントがデフォルトブラウザー内のプライベートなループバックワークスペースで開きます。バンドルされたエディタースキンは、ピン留めされた MarkNice エディターセクション（デュアルカード、信号機ヘッダー、SVG ツールバー、375px フォンフレーム）に、ローカルで非マーケティングなシェルが許す範囲で可能な限り近づけています。テーマ、レンダラー、数式組版、アプリケーションスクリプトはすべてオフラインで動作します。数式は自己完結型のインライン SVG（MathJax）として組版されるため、WeChat エディターの貼り付け時フィルタリングを重複なく通過します。ブラウザーでの編集はそのタブ内にとどまり、Markion に書き戻されることはありません。ワークスペースの **Word をインポート** は、そのブラウザーセッション内でのみ `.docx` を変換します。Markion に取り戻すには **MD をコピー** を使うか、セッションの Markdown を別の場所に保存してください。管理対象のローカル画像はプレビューできますが、ローカルの blob は WeChat に公開できないため、コピー時には明示的に除外されます。リモート画像は引き続き元のホストにアクセスする場合があります。ワークスペースでは、現在の Markdown をそのままコピー、テーマ適用済みのスタンドアロン HTML の保存、ブラウザー生成の MarkNice Word ファイルの保存、または現在のテーマ適用済みでサニタイズされたプレビューを印刷して **PDF として保存**（印刷ダイアログで「PDF として保存」を選択）することもできます。ブラウザーの Word/PDF は、Markion のネイティブ/Pandoc エクスポーターとは別物です。ワークスペースは Markdown ファイル、PDF、ローカル画像をインポートせず、サンプルドキュメントのアクションもありません。クリップボード権限または 2 時間のセッションが期限切れになった場合は、権限を許可するか Markion から起動し直してください。

## パフォーマンス

- プレビューブロック、ビジュアル編集ブロック、アウトライン、統計、行数はドキュメントのバージョンごとにキャッシュされ、`Arc` で共有されます。
- 構文ハイライトは編集をまたいでメモ化され、文法の読み込みはバックグラウンドで事前にウォームされます。
- 元に戻すスナップショットは派生キャッシュをスキップし、エディタはバージョンごとにキャッシュされたテキストハンドルを再利用します。
- プレビュー/ビジュアル編集のリストは変更範囲だけを更新し、ファイルツリーは制限された行セットを描画し、折り返されたソース行は実際のレンダリング高さを測定します。

ソースマッピングされたビジュアル編集は、局所的な編集後に独立して解析可能な領域を増分的に再利用し、Markdown のコンテキストやバイト範囲が不確かな場合は完全な再導出にフォールバックします。分割/閲覧プレビューの導出は、引き続きデバウンスとキャッシュが適用されます。Markion は rope ではなく `String` バッファーを使用しており、一部の意味的読み取りは意図的に完全なパースを必要とします。

## 現在の制限事項

- ビジュアル編集は正規の Markdown を保持しながら WYSIWYG 優先です。バイト精度のレンダリングが証明されていない構造は、推測によるリッチツリー変更を受け入れる代わりに、移行措置として正確なソースを公開し（[WYSIWYG カバレッジロードマップ](docs/visual-editing-quality.md)で追跡）、ブロックの並べ替えは重複しないソース境界が証明できる場合にのみ提供されます。現在の主なギャップは、デコード済み HTML エンティティ、フロントマター、インデントコードブロックです。二次的な不正形式または未サポートの構造は引き続きマトリックスに一覧されています。
- 画面レンダリング（分割/閲覧プレビューとビジュアル編集）では、組み込みの RaTeX エンジンで数式を組版します。LaTeX エクスポートは読み手自身のツールチェーンのためにネイティブの `$...$`/`$$...$$` ソースを保持し、組み込み DOCX エクスポートのフォールバック（pandoc が利用できない場合のみ使用）は、組版されたグリフを埋め込む代わりに、数式を読みやすいプレーンテキスト近似に縮退させます。
- ビジュアル編集のテーブルセルは直接編集に加えて、1 つのセル内に収まる選択範囲への太字/斜体/インラインコード/リンクをサポートします。GFM の列幅はドラッグでき、テーブル直前の HTML コメント（`<!-- markion-cols:… -->`）として永続化されます。インライン画像は 10〜100% の整数幅を受け付け、ドラッグでサイズ変更できます。参照式/複数行画像と不正形式のテーブルは、引き続き WYSIWYG カバレッジロードマップの既知のギャップであり、ソースベースの編集経路が維持されます。
- ワンクリック更新は Minisign 検証後に Windows NSIS ディストリビューションをインストールします。macOS バンドル置き換えと Linux `.deb`/AppImage の自己置き換えは将来の作業であり、更新の認証は Windows Authenticode や Apple 公証ではありません。
- ファイルツリーのドラッグ＆ドロップ移動と、完全なカスタムテーマのインストール UI は実装されていません。
- 画像エクスポートは基本的なテキストスナップショットであり、非常に大きなドキュメントでは、すべての派生サブシステムにまたがる rope や完全増分パースはまだ使用されていません。

## 開発

Rust stable が必要です。リポジトリのルートから：

```powershell
cargo run
cargo build
pwsh ./scripts/check-quality.ps1
```

品質コマンドは、Rust のフォーマットと lint、Cargo ワークスペース全体のテストスイート、ピン留めされた MarkNice バンドル、およびすべての OpenSpec アーティファクトを strict モードでチェックします。[ローカル MarkNice ワークスペースガイド](docs/marknice-workspace.md)と[ビジュアル編集のサポートとエンジニアリング契約](docs/visual-editing-quality.md)も参照してください。

ルートパッケージは `markion` アプリケーションクレートです。Typune 由来で GPUI に依存しないライブラリクレートは `crates/*` にあります：

```powershell
cargo test -p markdown
cargo test -p export
cargo test --workspace
```

通常の `cargo test` はルートパッケージのみをテストします。すべてのメンバーをテストするには `cargo test --workspace` を使用してください。Windows ではアプリは GUI サブシステムの実行可能ファイルであり、デバッグビルド後は次のように直接起動することもできます：

```powershell
.\target\debug\markion.exe
```
