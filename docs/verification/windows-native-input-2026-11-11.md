## 自动化接口恢复

`CODEX_CLI_PATH` 原先指向 `.../Codex/bin` 目录，启动该目录能稳定复现 Windows 原生错误 5；改为同目录的 `codex.exe` 后启动探针正常。用户重启 Codex 后，两个官方计算机控制入口均恢复。未修改 ACL、安全、隐私或锁屏策略。后续锁屏由用户解锁；窗口提供的 `Raise` 动作恢复了测试窗口焦点。

## 实机发现与修复

1. **中文提交后撤销恢复了临时拼音。** 真实按键 `n i h a o` 显示系统候选窗，停顿后空格提交“你好”，旧版 Undo 重新出现 `ni hao`。普通输入的 900 ms 合并超时错误地分割了仍在进行的 IME 会话。修复后 IME 以提交、取消和显式编辑边界结束捕获，普通输入超时保持原样。修复版候选选择停顿约 4.15 秒后，Undo 恢复原文，Redo 恢复“你好”，Escape 不残留拼音。
2. **清空表格矩形选区时视口跳动。** 已显示的表格因内容变化失去测量值，被预布局光标定位误认为屏幕外的新行。现在仅在源码归属和已显示范围均可验证时等待新单元格几何，再按实际溢出量微调。屏幕外和新建行继续使用原有定位路径。
3. **代码块 Copy 按钮跳到左侧。** 隐藏语言编辑芯片后，单独的 Copy 子元素失去了两端对齐的占位。自动左边距使其保持在右侧。

撤销快照仍不持有派生缓存；没有新增文档级缓存、依赖或每键完整解析。

## 回归与测量口径

新增两项 IME 候选停顿回归和一项表格视口回归，均先观察失败再修复。最终根包桌面测试 **788 通过、2 个既有忽略项、0 失败**。格式检查、`git diff --check` 和变更规范校验通过。

`Invoke-FluentEditingSmoke.ps1` 仍是原生窗口中的应用回调回放，本次增加候选停顿和表格视口断言。它与上面的 OS 输入测试分别记录，不能将回放本身解释为系统候选窗验证。

输入时间从应用收到输入回调计算到当前版本光标 paint；打开时间从应用读取文档计算到正文 paint。两者不包括完整 OS 输入传输或 GPU 呈现。RSS/Private 来自独立测试进程，不包含构建进程；显存未单独测量。
