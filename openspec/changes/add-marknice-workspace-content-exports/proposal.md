## Why

The local MarkNice workspace permits session-local Markdown edits but currently offers no MarkNice formatting controls, no plain-source recovery path, and no way to preserve the resulting MarkNice presentation outside the clipboard workflow. Users need efficient browser-local formatting and explicit exports for the current session so those edits and publishing choices can be retained without writing them back into the Markion document.

## What Changes

- Add a **Copy Markdown** action that copies the exact current browser-session Markdown as `text/plain` and reports success or actionable clipboard failure.
- Add a P0 MarkNice-style Markdown formatting toolbar and Ctrl/Cmd shortcuts for headings, emphasis, lists, code, links, quotes, image syntax, and tables. Formatting changes only the browser session's textarea, preserves the active selection/caret where practical, and immediately refreshes the preview.
- Add a **Download themed HTML** action that exports the current sanitized MarkNice output, including the selected publishing theme, font-size offset, paragraph-spacing offset, rendered math, and safely embeddable managed local images.
- Add a **Download DOCX** action that ports the pinned MarkNice browser-side Word export path and generates the document entirely in the browser from the current session output.
- Vendor the pinned browser DOCX runtime locally, record its provenance, digest, and license, and keep every export action available without CDN or hosted MarkNice access.
- Ensure downloaded HTML and DOCX artifacts contain no session capability, bearer token, loopback URL, blob URL, filesystem path, executable authored content, or unresolved protected-resource reference.
- Add localized labels, formatting placeholders, accessible names, progress, success, empty-content, resource-fallback, compatibility, and failure feedback, plus browser compatibility and package-verification coverage.
- Build on the implemented and strictly validated `add-local-marknice-publishing-workspace` baseline while its remaining cross-platform/browser/WeChat manual evidence is collected in parallel; both changes still require that evidence before release or archive.
- Non-goals: synchronizing browser edits back to Markion, replacing Markion's native HTML or DOCX exporters, adding browser PDF export, importing Markdown/DOCX/PDF, uploading images, saving to the WeChat draft box, or bundling a Node service or remote credentials. The toolbar may insert Markdown image syntax, but it does not upload or import an image.

## Capabilities

### New Capabilities

- `wechat-workspace-content-export`: Covers MarkNice-style browser-local Markdown formatting, plain Markdown copying, and safe browser-local themed HTML and DOCX downloads from the current local publishing session.

### Modified Capabilities

None.

## Impact

- Affected browser assets include the editor-only workspace shell, generated formatting runtime, bridge/export JavaScript, workspace styles, compatibility corpus, self-tests, and localized strings delivered with the publishing snapshot.
- The checked-in workspace bundle gains a pinned local `html-docx-js` browser runtime and its license/provenance records; bundle digest generation, dependency-closure verification, release packaging, and packaged-resource checks must include it.
- HTML and DOCX export preparation operates on a sanitized clone of the current browser preview and may transform protected managed images into export-safe embedded data without widening the immutable session resource allowlist.
- No new loopback mutation or export endpoint is introduced. Downloads are generated by a user gesture in the authenticated browser tab, and the Markion document, dirty state, version, selection, undo history, and shared derived-cache identities remain unchanged.
- Browser-generated DOCX remains distinct from Markion's native/Pandoc DOCX pipeline and targets the compatibility envelope documented for the pinned MarkNice `html-docx-js` implementation.
