## 2. File-tree scan filter (core behavior, fully unit-testable)

- [x] 2.1 In `src/storage/file_tree.rs`, split `should_skip_file_tree_path` (~lines 323-357) into two pure functions: `is_always_excluded(path)` carrying the existing hard-coded noise list byte-for-byte (`.git`, `target`, `node_modules`, …), and `is_hidden_entry(path, show_hidden)` returning `true` only when `show_hidden == false` **and** the entry is OS-hidden. OS-hidden = file name `starts_with('.')` (applies to files **and** dirs, fixing the current `is_dir()`-gated asymmetry) **or**, on Windows, the hidden file attribute. Keep `should_skip_file_tree_path` as a thin wrapper `is_always_excluded(path) || is_hidden_entry(path, show_hidden)` so call-site behavior is unchanged when `show_hidden == false`.

On `metadata` error, treat the attribute check as "not hidden" (best-effort) — the dotfile check still applies independently. Guard the `use` of `MetadataExt` with `cfg(windows)` so non-Windows builds compile cleanly.

Change the existing `pub fn scan(root: &Path) -> FileTree` (~line 48) into a thin wrapper `Self::scan_with_options(root, false)` so the other call sites (`src/app/workspace.rs` ~lines 650, 670) and existing tests keep compiling unchanged.
