## Context

See proposal.md. Right-click still uses heading/list submenus, while `from_grip` selects a separate hard-coded 14-transform layout and scroll mapping. Slash/emoji palettes already share panel/button styling in `root_view.rs`. Existing block targets, insertion editors, clipboard actions, and image policies provide the required editing paths.

## Goals / Non-Goals

**Goals:** Shared compact presentation with both block and fine-editing commands in the right-click menu, and independently captured, exact source ownership for each command family.

**Non-Goals:** New formatting syntax or general/native-menu redesign. The existing grip/slash layout remains unchanged; the editing context menu exposes H1–H5 directly and the Insert flyout offers H1–H5; H6 remains supported outside the context menu.

## Decisions

- Extract the 248px panel and 30px button primitives into a shared application module consumed by completion and block menus. Preserve active-theme colors, localization/tooltips, rounded corners and shadow. Render 36px-wide icon controls with 2px gaps. Reusing primitives prevents later visual drift.
- Replace heading/list/image submenus with a flat catalog grouped into selection formatting, direct block transforms, labeled insertion/image actions, clipboard/block controls and destructive Delete. Build rendering and keyboard scroll-to-row mapping from the same grouped catalog rather than positional constants. Compact controls are chunked into rows of six and labeled actions into individual rows so even a section taller than a short viewport stays operable. Right/Left move through the flat catalog; Up/Down, Enter and Escape retain navigation/confirmation/dismissal semantics.
- Right-click and keyboard context menus capture document identity/version, the canonical text/structured selection, an effective text range, the clicked block and optional row/column targets. Retain block transforms, duplication, movement, Add Below, explicit Delete Block and image controls alongside fine editing. Copy/Cut/Paste/Delete Selection never silently expand to a block; the grip catalog retains its whole-block clipboard commands. Both catalogs share layout primitives and scrolling.
- In block commands, add Link/Formula/Image settings and Paste only when the clicked block has proven editable prose content. Use the captured exact selection if it belongs to that block, otherwise a caret inside editable content, otherwise the editable content end. Editing menus instead require the captured current range itself to have exact editable ownership. Revalidate target/version and the captured selection before activation. Settings share the slash editor initializer but use the captured insertion range without deleting or creating placeholder text; cancel leaves source/selection/cache identity unchanged. Confirmation follows existing versioned editor/resource paths.
- Editing clipboard/deletion commands use the existing document/structured-selection paths, bypassing unrelated search/name-field focus. Selection Copy/Cut/Delete are disabled for a caret. Preserve active selections; with no selection, derive the exact text location from current painted navigation geometry (restricted to the clicked cell when applicable), and use the caret for keyboard invocation. Paste and inline-format/settings commands use that effective range; block commands continue to use the clicked block. Revalidate all captures before activation. Add Strikethrough to the canonical inline wrapper and single-cell format allowlist.
- Capture row/column targets from an explicit cell pointer handler, the exact text hit, or the keyboard-owned/structured-selection head cell. The combined menu reuses existing table item catalogs, localized labels, disabled-state resolver and checked structural mutations. Keep row/column groups visibly distinct from block movement/deletion; header, first/last row and first/last/lone-column restrictions remain unchanged.
- Settings anchors use caret geometry only when the caret belongs to the settings source block; otherwise they use that source block's bounds, preserving an unrelated selection without placing the pane beside it.
- Data flow: cached Visual blocks + canonical selection → captured target/selection → grouped transient menu → shared palette rendering → target/selection validation → existing exact block edit, settings editor, clipboard or resource path. Opening, hover, scrolling, keyboard highlight and dismissal do not change document version, history or shared derivation caches.
- Table text and padding consume left-click events before the workspace click-away handler. The menu panel must therefore dismiss outside clicks in the capture phase, before cell handlers can stop bubbling, including same-cell clicks outside the panel. New-tab, replace, switch, close and bulk-removal transitions clear document-bound menus, insertion editors and completion overlays before changing active document identity. Rendering discards stale block/table menu targets and omits an invalid overlay rather than assuming every stored target is live; image tabs are rejected before accessing document-only state.

## Risks / Trade-offs

- Cell-context roots exclude all block conversions and block/image insertion; whole-table duplicate/move/delete remain explicit. Link uses the safe inline-format action when present, avoiding the second insertion control. Row/Column replace the root contents with a second-level list in the same panel, keeping capture-phase outside-click dismissal valid. Back/Left returns to the parent and Right/Enter opens a selected submenu; disabled operation guards remain shared.
- Pointer highlight callbacks capture their originating page. A queued root callback must not interpret its old index in a newly opened row/column page (or vice versa), where the same index can denote a destructive action. Reject those callbacks before changing keyboard selection.
- Shift+Enter has a dedicated cell branch before ordinary Enter traversal. Insert `<br>` through the existing direct-field replacement sanitizer and atomic undo path; use its exact source range and selection mapping, with no table reserialization.
- Investigate code background overflow with native reproduction and rendered bounds across document switches. Constrain the code surface itself to its parent column and verify intrinsic long-line sizing rather than invalidating document-derived caches or hiding the symptom through global clipping.

- [More commands increase height] → compact grids, grouped rows, bounded menu-local scrolling, and keyboard scrolling to the same section layout.
- [A right-click target differs from the caret or selected text] → retain independent immutable block, effective text and cell targets; preserve active selections and use painted pointer geometry only for a collapsed selection. Reject stale captures.
- [Retiring submenus changes navigation tests] → replace submenu assumptions with direct-control, flat navigation, disabled-state and full-catalog reachability checks while retaining existing mutation/undo assertions.
- [Resource dialogs are unavailable on the GPUI headless platform] → exercise insertion transactions automatically and verify native dialogs through an isolated Windows app/profile.

## Migration Plan

### Installed Typora comparison and revised context model

See `typora-comparison.md` for historical observations from the installed Windows application. The latest requested layout supersedes that comparison's paragraph and table organization: ordinary prose/headings expose their complete format/action controls directly at the top, followed by selection clipboard/inline controls and a bottom Insert flyout. Table menus use separate Row and Column flyouts and root whole-table actions. Images retain Properties, scaling/alignment and resource commands. Grip command grids remain available. Selection clipboard/inline actions retain independent captured selection scope. Destructive/whole-unit labels identify Table, Image, Heading or Paragraph explicitly.

The Insert catalog uses distinct insertion actions, never block transforms. Reuse slash templates for paragraph, H1–H5, list, task, quote, code, divider and table blocks; add the five supported GFM alert templates. A checked block edit inserts after the complete source unit (including nested list children or the entire quote), preserves surrounding bytes and LF/CRLF, separates both neighbors, places the caret in the new editable payload and commits one undo entry. Inline Link/Formula/Image settings retain captured exact selection/caret targeting and non-mutating cancellation. Root and child catalogs continue to drive both rendered rows and keyboard scrolling.

Empty plain whitespace rows are insertion targets, independently of reorder/delete eligibility. Resolve the exact blank line from pointer Y or the keyboard caret, validate its version/identity/range and whitespace-only content, and reuse that line for block templates with deterministic separators. Selection clipboard/delete guards remain unchanged. Link/Formula/Image settings accept a proven empty range there. The empty-row root heading reads Format Block. Non-empty clicked units retain after-unit insertion.

For marker-only callout leaves, partition the first authored marker line from any following quoted blank body lines in the per-version visual derivation. Keep disjoint contiguous source ownership, quote-group alert styling and an actual body-height click target; the insertion caret and subsequent clicks land after the body's quote prefix. Normal styled-title clicks choose the first existing body payload/blank line using cached visual metadata. Explicit keyboard/source entry into the marker/title retains progressive source reveal. Opening menus and moving the caret never insert placeholder text or reparse on hover.

Flyouts open on parent hover or Right/Enter/click, remain beside the root, flip to the left near the viewport edge, scroll independently and fit short windows. Captured root/child geometry and parent-row bounds drive placement and capture-phase outside-click exclusion. Entering the child or the small bridge must not dismiss the root. Hovering another root control replaces/closes the child; stale page/target callbacks cannot retarget keyboard selection. Geometry updates do not notify/reparse document state.

Images render directly without constructing a raw payload surface or consulting expansion/hover/failed-source state. A Properties action opens existing localized URL/label/title fields using a dedicated editor kind; confirmation revalidates the captured document generation and exact occurrence and writes one checked mutation. No-op/cancel and changing width/alignment preserve authored reference syntax; an explicit changed reference property may convert only that occurrence to inline form, leaving definitions and other occurrences untouched. Full Source mode continues to own raw Markdown editing. This preserves per-version caches and eliminates image payload projection clones from hover/selection paints.

No persistence or content migration. Keep existing preference names/defaults and reversible application-only changes. This delta intentionally supersedes earlier unarchived menu-presentation decisions while preserving their selection/reordering behavior.
